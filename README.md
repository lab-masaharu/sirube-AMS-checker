# sirube-ams-checker（差分管理システム / Phase 0 第一歩）

AMS（agent-master.jp）にログインして物件リストを巡回し、各物件の **object_id** と
**媒体（ふれんず / SUUMO / athome / HOME'S / 自社）** を仕分けして一覧化する確認スクリプトです。

このフェーズの目的は **「779件をちゃんと取得できるか」だけ** を確認することです。
突合・DB保存・書き戻しはまだ行いません。

- system_code: `sys_ops_ams_checker`
- 認証情報は `.env` から読み込みます（コードに書きません）

---

## 0. 用意するもの

- パソコン（Windows / Mac / Linux どれでも可）
- AMSのログインID・パスワード

---

## 1. Node.js を入れる（すでに入っていれば飛ばす）

ターミナル（Windowsは「コマンドプロンプト」または「PowerShell」）で確認:

```
node -v
```

`v18` 以上の数字が出ればOK。`'node' は…認識されていません` 等が出たら未導入です。

未導入の場合 → https://nodejs.org/ja の「LTS」版をダウンロードしてインストール。
インストール後、ターミナルを開き直して `node -v` を再確認。

---

## 2. このフォルダで準備をする

ターミナルでこのフォルダ（`sirube-ams-checker`）に移動してから:

```
npm install
npx playwright install chromium
```

- `npm install` … 必要な部品（playwright, dotenv）を入れる
- `npx playwright install chromium` … 操作用のブラウザ本体を入れる（初回のみ・少し時間がかかります）

---

## 3. .env を作って認証情報を入れる

テンプレートをコピーして `.env` を作ります。

Windows（コマンドプロンプト）:
```
copy .env.example .env
```

Mac / Linux:
```
cp .env.example .env
```

できた `.env` をメモ帳などで開き、次の2つを埋めます:

```
AMS_EMAIL=（あなたのAMSログインメール）
AMS_PASSWORD=（あなたのAMSパスワード）
```

> `.env` は Git に上がらないよう設定済みです（.gitignore）。
> このファイルは他人に渡さない・チャットに貼らないでください。

---

## 4. 実行する

```
npm run crawl
```

初回は `HEADLESS=false`（.envの初期値）なので、**ブラウザ画面が実際に開いて**
ログイン → リスト取得 の様子が見えます。うまくいけば、最後に次のような
サマリーが表示されます:

```
========== 巡回結果サマリー ==========
AMS総件数(画面表示): 779
取得した物件行数  : 779
ユニークobject_id : 779（重複 0）
--- 媒体内訳 ---
  ふれんず(突合対象): 123
  SUUMO            : 200
  athome           : 50
  HOME'S           : 80
  その他リンク      : 10
  リンクなし(自社等): 316
=====================================
```

（数字は例です。実際の内訳は物件状況によります）

詳細は同じフォルダにできる **`results.json`** に保存されます。

---

## 5. うまくいかないとき

- **ログイン画面で止まる** → `.env` のメール／パスワードを確認
- **途中で止まる** → `HEADLESS=false` のままなら、どの画面で止まったか目視で確認できます
- **動作を軽く試したい** → `.env` の `MAX_PAGES=2` にすると最初の2ページだけ取得して終わります
- エラーメッセージはすべて構造化ログ（JSON）でターミナルに出ます。`"level":"ERROR"` の行を見てください

---

## 6. 次のステップ（このあと）

1. `results.json` の中身（特に媒体内訳）を一緒に確認
2. ふれんず物件のステータス取得方法を確定
3. データ構造（物件マスタ／差分ストア）を確定
4. n8nで「共通部分（巡回→振り分け→承認）」の骨組みを構築
5. 媒体ごとのサブワークフローを順次追加
